# Q1.1 双评审与收口操作说明

版本：2026-09-24  
状态：分析程序已就绪；真实人工评分尚未开始（0/7,930 个评分单元）。

## 1. 角色隔离

- 评审 1 和评审 2 必须独立完成全部 793 条文本的五维 1–5 整数评分，评分期间不得查看对方分数。
- 两位评审只能收到 `results/q1_1/v1/review_packet/blind_review_samples.md`、评分标准和各自的评分表副本。
- 两位评审不得查看 `restricted_id_mapping.csv`、`sample_scores.csv.gz`、`q_equal`、`q_huber`、来源域或任何自动评分结果。
- 协调者在两份评分均锁定后再合并；不得根据一致性或相关结果要求评审修改原分。
- 给两名评审分配非空且不同的审计标识，例如 `R1-20260924`、`R2-20260924`。标识可以匿名，但必须能证明是两名不同评审。

## 2. 评分表放置

原始空表位于：

`results/q1_1/v1/review_packet/blind_review_form.csv`

不要覆盖原始空表。请在 `zwj/` 内建立工作副本，例如：

- `zwj/q1_1_review_working/rater_1_form.csv`
- `zwj/q1_1_review_working/rater_2_form.csv`
- `zwj/q1_1_review_working/blind_review_form_filled.csv`

两份独立表保持 793 个 `blind_id` 和原顺序不变。评审 1 只填写 `rater_1_*` 五列，评审 2 只填写 `rater_2_*` 五列；协调者把两组已锁定分数按 `blind_id` 合并到最终工作表。不要复制行号匹配，必须按 `blind_id` 连接。

五个维度为：

1. `education`：教育用途；
2. `readability`：可读性；
3. `coherence`：连贯性；
4. `information`：信息传递；
5. `overall`：整体质量（主效标）。

评分只能是 1、2、3、4、5；不得留空，不得使用小数、文字或特殊缺失码。

## 3. 完整性检查

在仓库根目录执行：

```powershell
python zwj/q1_1_human_validation.py `
  --ratings zwj/q1_1_review_working/blind_review_form_filled.csv `
  --rater-1-id R1-20260924 `
  --rater-2-id R2-20260924 `
  --check-only
```

只有返回 `status: ready`、`filled_score_cells: 7930`、`candidate_score_links: 793` 时才能进入正式分析。退出码 2 表示输入未就绪或合同错误；此时不会创建正式结果。

## 4. 正式分析

移除 `--check-only`，其余参数保持不变：

```powershell
python zwj/q1_1_human_validation.py `
  --ratings zwj/q1_1_review_working/blind_review_form_filled.csv `
  --rater-1-id R1-20260924 `
  --rater-2-id R2-20260924
```

正式结果只写入：

`zwj/results/q1_1_human_validation/`

包括一致性表、七域相关表、bootstrap 汇总、中文报告、JSON 摘要和复现清单。程序固定使用 2,000 次实际层内配对 bootstrap 和随机种子 20260924。

## 5. 结果解释门禁

- 整体质量设计加权 Kappa 必须满足：点估计 ≥ 0.40、95% 区间下限 > 0、有效重复比例 ≥ 95%。失败时不以双评均值选择唯一候选。
- `q_equal` 宏相关、`q_huber` 宏相关及两者差值的区间半宽都必须 ≤ 0.15，且有效重复比例都必须 ≥ 95%。
- 若基础结果支持 Huber 优于等权，但缺少各预设敏感性场景下 793 条记录的候选分，程序会保守地阻止唯一统计选择。
- `q_huber` 作为下游操作接口的治理冻结，与人工统计胜出分开记录。
- A2/A3 缺少可追溯原文及一一 ID 映射；即使 A1 通过，也只能写“A1 范围内验证、扩展集受限”。
