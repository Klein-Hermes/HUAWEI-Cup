# 定稿自检清单

> 全部条目的来源：**5 篇往届优秀论文的实际硬伤**（B题 MIMO-OFDM 76页 / C题 围岩裂隙 78页 /
> E题 轴承迁移 93页 + 69页 / F题 园林美学 116页），逐篇精读时发现的真实错误。
> 这些论文已经拿到"优秀"，仍然带着这些错——**说明评委看得到，只是没到取消资格的程度**。
> 定稿前逐条打钩，零成本拉开差距。

---

## A. 编号与交叉引用

- [ ] **表号/图号连续无重复**
      真实案例：B题论文 `表4-1` 出现了两次（第二处应为 `表4-3`）
- [ ] **交叉引用全部重编译，无 `??`**
      真实案例：C题论文正文留了 `如下表??：`
- [ ] **无 Word 域代码残留**
      真实案例：E题B篇留了 `LSTM 模型结构如错误!未找到引用源。所示。`
- [ ] **公式编号连续无跳号**
      真实案例：E题B篇从 `(38)` 直接跳到 `(42)`
- [ ] **公式是可编辑文本对象，不是图片**
      真实案例：E题B篇全篇公式是图片，评委无法检索/复制
- [ ] **目录标题与正文标题一字不差**
      真实案例：E题B篇目录写"无监督领域自适应网络迁移诊断"，正文写"基于Vision
      Transformer的领域自适应无标签故障诊断"
- [ ] **公式要么全编号、要么不引用编号**
      真实案例：C题论文正文引"式（3）"，但全文公式无编号
- [ ] **每问都配了思路流程图**
      真实案例：C题论文问题四缺流程图；E题A篇问题四缺
- [ ] grep 命令：
      `grep -n "??" tmp/paper.log`
      `grep -nE "Reference|Citation.*undefined" tmp/paper.log`

---

## B. 数字一致性（最容易翻车）

- [ ] **摘要里每个数字都能回到正文表图**
      真实案例：B题论文摘要问题三写 `R²=0.702，RMSE=62.195`，但正文表里
      0.702 与 62.195 **分属两个不同模型**——串位了
- [ ] **同一指标在全篇（摘要 / 正文 / 优缺点章）三处一致**
      真实案例：E题A篇缺点章写"筛选出的19个特征"，全文其他地方都是 14
- [ ] **摘要列举的数值条数与表格行数一致**
      真实案例：C题论文摘要列了 7 个 JRC 值，表里有 8 条裂隙（漏了一个）
- [ ] **表头量纲正确**
      真实案例：B题论文 `表5-3 模型拟合指标（dB）` 里把 R² 标成"均方误差"；
      `表5-2 ...（dB）` 的 α/β 实际无量纲
- [ ] **正文提到的统计量确实报了数值**
      真实案例：F题论文写了 MANOVA/Wilks' Λ、配对 t 检验、Sobol 敏感度指数，
      但**一个数值都没报**——方法写了、结果没做，等于没做
- [ ] **判据与结论不矛盾**
      真实案例：F题论文写"κ>0.8 认为一致性极好"，表里评估标准却设"κ>0.833"，
      而结果恰好是 0.833——判据等于结果，且按">"号并未达标，结论却写"良好"
- [ ] 做法：定稿前把摘要打印出来，逐个数到正文表里找。**不要凭记忆。**

## C. 逻辑与内容

- [ ] **前后结论不打架**
      真实案例：C题论文 3.1 节写"经过比对发现 YOLOv8 效果更好"，但摘要、
      3.6.1、3.7 最终选的都是 Canny——**3.1 是没改干净的残留**，评委一眼看到逻辑打架
- [ ] **没有残留占位符**
      真实案例：E题A篇留了未删的 `text`；F题论文正文留了 `图x`
- [ ] **没有超纲引入的概念**
      真实案例：E题B篇讨论了赛题里根本没有的"保持架故障 FTF"
- [ ] **摘要里的答案与最终结果一致**
      正例：E题A篇把 `4个外圈/4个内圈/5个滚动体/3个正常` 直接写进摘要
- [ ] **关键词格式规范**（全角分号或 \quad 分隔，不用空格；取模型名/方法名）
      真实案例：E题A篇关键词用空格分隔（排版瑕疵）
- [ ] **全文查重字**
      真实案例：E题B篇"在复杂工况下容易**易**损坏"；C题论文"方向一致性**一致性**"
- [ ] **假设不是套话**：每条有"依据→简化→偏差→验证位置"
- [ ] **结论没有把预测/仿真写成因果/诊断/现实最优**
- [ ] **"模型精度高、适用性广"这类话必须有正文证据支撑**

## D. 格式与工程

- [ ] **编译 2 遍**（交叉引用与目录需要二次编译才正确）
- [ ] **PDF 字体已嵌入**（xelatex 默认嵌入，用 `pdffonts` 或预览器确认）
- [ ] **页数符合当年要求**（以《竞赛论文标准文档》为准，比赛期间去研创网核验）
- [ ] **摘要页符合规范**（题目、摘要、关键词都在摘要页；不超过两页）
- [ ] **正文无任何身份标识**（学校名、队号、队员姓名只出现在封面）
- [ ] **参考文献全部被正文引用过**，且引用处都在
      真实案例：F题论文 [10][11][12] 全文未被引用，只躺在文献表里
- [ ] **参考文献条目格式统一**（GB/T 7714；中英文混排检查卷期页完整）
      真实案例：F题论文 [5] 有断行残缺、[6] 条目内嵌了多余的 `[1]` 标记
- [ ] **附录按问题分块**，函数名与正文模型名对应
- [ ] **附录代码开头写清运行环境与依赖**

---

## E. 收尾时间线

- [ ] 终稿冻结前 **≥1 小时** 留作缓冲（网络/平台问题）
- [ ] 提交后**截图留证**
- [ ] ⚠ 2026 年提交是**双窗口**：
      · MD5 码提交：09-26 12:00 至 **09-27 12:00**（= 竞赛结束时刻，PDF 必须已冻结）
      · PDF 上传：09-27 14:00 至 09-28 24:00
      **内容冻结在 09-27 12:00，上传晚了也改不了内容**

---

## 使用方式

```bash
./build.sh          # 编译 + 自动检查（未定义引用 / 参考文献条数 / 错误数）
```

然后人工过 A→B→C→D 四组清单。**B 组（数字一致性）建议两人交叉核对**，
因为作者对自己写的数字有盲区。
