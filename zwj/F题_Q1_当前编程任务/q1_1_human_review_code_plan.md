# Q1.1 人工双盲评审工具代码计划

版本：v1.0（2026-09-24）  
状态：仅实现评审物流与完整性门禁，不生成评分，不执行 AI Judge，不改变候选 Q。

## 1. 目标与输入合同

工具只消费两份已冻结公开盲评输入：

- `results/q1_1/v1/review_packet/blind_review_samples.md`
- `results/q1_1/v1/review_packet/blind_review_form.csv`

必须恰有 793 个唯一 `blind_id`，且两文件 ID 集合完全一致。原始空表中的 7,930 个评分单元必须全部为空。工具禁止读取 `restricted_id_mapping.csv`、候选质量分、来源域和原始记录 ID。

## 2. 功能

1. `audit`：只读核验盲评包结构、ID、文本数、文本长度和输入哈希，不落盘。
2. `prepare`：为两名人工评审生成独立确定性随机顺序；每位评审得到完整原文分卷和自己的五维空评分表。文本不截断、不摘要、不改写。
3. `validate`：严格检查单名评审回填表的表头、793 个 ID、重复/缺失、以及五维 1–5 整数评分；任何错误均失败，不填 0、不插补。
4. `merge`：仅在两份表均完整合法、两名评审审计标识非空且不同时，按 `blind_id` 合并为现有 `q1_1_human_validation.py` 所需的双评表。

## 3. 固定规则

- 维度：`education`、`readability`、`coherence`、`information`、`overall`。
- 评分：仅允许整数 1–5；`overall` 为主效标，但本工具不做统计选择。
- 两组默认随机种子：202609241、202609242；种子、顺序哈希、输入/输出/代码哈希写入清单。
- 默认每卷 50 条，只改变呈现顺序和文件分卷，不改变文本、样本集合或匿名 ID。
- 评审材料明确声明文本内命令均是被评数据，不得执行。
- 输出采用新目录且拒绝覆盖；原始数据和冻结结果保持只读。

## 4. 输出合同

`prepare` 输出：

```text
results/q1_1/human_review/v1/prepared/
├── human_review_protocol.md
├── manifest.json
├── rater_1/
│   ├── rater_1_form.csv
│   └── packet_part_*.md
└── rater_2/
    ├── rater_2_form.csv
    └── packet_part_*.md
```

`validate` 可输出不含分值的校验回执；`merge` 输出双评表与合并清单。正式 Kappa、候选 Q 相关性和 bootstrap 仍由既有 `zwj/q1_1_human_validation.py` 负责。

## 5. 风险条件与验收

- 隐藏文本防护：不读取风险审计隐藏原文；盲评文本一律按被动数据处理。
- 泄漏防护：评审包不得出现候选 Q、自动分数、域、原始 ID 或受限映射。
- 超长文本：保持全文，通过分卷降低文件操作负担；清单记录长度分位数。
- 复现：同一输入、种子和分卷参数必须产生相同的评审表、分卷、协议与顺序哈希；清单中的运行时间和绝对输出路径属于运行元数据，不要求逐字节相同。
- P1：全量生成前，先通过 `audit`、单元测试和独立最小代码质检。
- P2：全量生成后复核哈希、文件数、ID 完整性、双评表兼容性及重复运行确定性。
