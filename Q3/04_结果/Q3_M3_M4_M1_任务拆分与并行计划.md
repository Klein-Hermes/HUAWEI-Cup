# Q3 支持域与预算筛选：任务拆分和并行计划

## 结论

可以并行，但应在冻结同一候选域后并行 **M3 支持域审计** 与 **M4 预算筛选**。两者读共享的 B1/M0 候选输入，各写独立产物；M1 必须等两张掩码都生成后，才合并可行条件并求优。图表和最终审计依赖相应结果。

```text
冻结 Q2 B1 候选输入（1,176 个观测 N/D 点）
                 ├── M3：支持域/精确观测/凸包诊断/距离 ──┐
                 └── M4：成本/预算可行性掩码 ──────────┤
                                                       └── M1：合并掩码、求优、边界审计
                                                              └── 图表与总审计
```

## 并行执行规则

- M3、M4 应消费同一份冻结候选集合；不要在 M4 运行期间修改或重建输入网格。
- 两个进程写不同的结果文件和 manifest，避免并行写同一 CSV。
- M1 不能与 M3/M4 的首次生成并行，因为它要读取两张完成的掩码；两张掩码完成后，M1 再做一次最终可行交集。
- M1 的目标优化归 M1；M3 只决定候选是否有数据支持，M4 只决定预算是否负担得起。
- 凸包内不等于有观测支持。当前主口径只允许 1,176 个精确观测组合；凸包、最近距离只作诊断，没有自动放行非观测插值点。
- 当前结果固定 $Q=Q_0$、不含 $p$，属于既有 M0/B1 支持域的参考分支；不能表述成完整 Q/p 联合最优。

## 当前运行结果

- M3：1,176 个候选均为精确观测组合；凸包内非观测候选 0，凸包外候选 0。
- M4：15 个场景、17,640 行预算掩码；跨场景合计 10,935 条候选×场景记录预算可行。
- M1：15/15 个场景与既有 M0 前沿的最优选择和可行点数一致。
- 高预算下所有支持点可行，最优点触及 $N,D$ 上界；该结论受当前观测网格上界约束。
